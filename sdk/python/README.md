# feld-sdk

The Python SDK of the Feld daemon API. How to install and use it is in [`docs/guide/python-sdk.md`](../../docs/guide/python-sdk.md).

## Layout

The public API is written by hand on top of a private layer generated from [`docs/guide/daemon-api.openapi.yaml`](../../docs/guide/daemon-api.openapi.yaml).

- `src/feld/_api/`, `src/feld/_models/`, `src/feld/_client.py`, `src/feld/_errors.py`, `src/feld/_types.py`: generated by `openapi-python-client` with the templates in `templates/`. Edit the definition, `scripts/generate.py`, or the templates, not these files
- `src/feld/client.py` (`feld.Client`), `resources/` (its operations, one module per resource) and `_resource.py`, `models.py` (the public types, re-exported from `_models`), `connect.py`, `exceptions.py`, `testing.py`: written by hand

`scripts/generate.py` hands the generator a pruned copy of the definition:

- the operations of the tags `Daemon` (its reads `getDaemonStatus`, `listRuntimes`, `listProviders`), `Workspace`, `Actor`, `Session`, `Message`, `Record`, and `Events`, and the components they reach
- free-form objects (such as the Provider's `placement`) as `dict[str, Any]`, which `templates/model.py.jinja` declares
- inline schemas that `feld.models` exports given names (`NAMED*`)

## Regenerating

Run `make sdk` at the repository root after changing the OpenAPI definition, and commit the result. `make check` regenerates and fails when the committed files differ, then runs mypy and pytest. Both need [uv](https://docs.astral.sh/uv/).
